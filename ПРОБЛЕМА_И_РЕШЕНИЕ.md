# ⚠️ НАЙДЕНА ПРОБЛЕМА: Сервер недоступен по SSH

## 🔍 Что произошло

Сервер **49.13.52.51** не отвечает на SSH подключения (порт 22). Поэтому GitHub Actions не может подключиться к серверу для деплоя.

**Ошибка**: Connection timeout на порту 22

## ✅ Что нужно сделать

Необходимо открыть SSH доступ к серверу. Вот пошаговые инструкции:

### Вариант 1: Через панель Hetzner (Рекомендуется)

Судя по IP адресу (49.13.52.51), это сервер Hetzner. Действуйте так:

1. **Войдите в Hetzner Cloud Console**: https://console.hetzner.cloud/

2. **Выберите ваш сервер** (49.13.52.51)

3. **Проверьте Firewall**:
   - Откройте раздел "Firewalls"
   - Убедитесь, что SSH (порт 22) разрешен
   - Добавьте правило, если нужно:
     - Протокол: TCP
     - Порт: 22
     - Источник: 0.0.0.0/0 (все IP адреса)

4. **Проверьте статус сервера**:
   - Сервер должен быть в статусе "Running"
   - Если выключен, нажмите "Power On"

5. **Используйте веб-консоль**:
   - Нажмите кнопку "Console" в панели сервера
   - Это даст прямой доступ даже если SSH заблокирован
   - Оттуда можно настроить firewall

### Вариант 2: Через консоль Hetzner (прямой доступ к серверу)

Если вы можете получить доступ через веб-консоль Hetzner, выполните:

```bash
# Проверить, запущен ли SSH
systemctl status ssh

# Запустить SSH если не запущен
systemctl start ssh
systemctl enable ssh

# Проверить firewall (если используется ufw)
ufw status

# Разрешить SSH через firewall
ufw allow 22/tcp
ufw allow 80/tcp

# Или временно отключить firewall для теста
ufw disable

# Проверить, слушает ли SSH
netstat -tlnp | grep :22
```

### Вариант 3: Проверить iptables

```bash
# Посмотреть текущие правила
iptables -L -n

# Добавить правило для SSH
iptables -I INPUT -p tcp --dport 22 -j ACCEPT

# Также разрешить HTTP
iptables -I INPUT -p tcp --dport 80 -j ACCEPT

# Сохранить правила
iptables-save > /etc/iptables/rules.v4
```

## 🎯 Быстрое решение (если есть доступ к консоли)

Если у вас есть доступ к веб-консоли Hetzner:

```bash
# Установить и настроить firewall
apt-get update
apt-get install -y ufw openssh-server

# Разрешить нужные порты
ufw allow 22/tcp   # SSH
ufw allow 80/tcp   # HTTP (для приложения)
ufw --force enable

# Перезапустить SSH
systemctl restart ssh
systemctl enable ssh
systemctl status ssh
```

## 🆘 Частые проблемы

1. **Firewall блокирует**: Самая частая причина
   - Решение: Откройте порт 22 в firewall

2. **Сервер выключен**: Проверьте в Hetzner панели
   - Решение: Включите сервер

3. **SSH не установлен**: Редко на Hetzner
   - Решение: `apt-get install openssh-server`

4. **Неверные учетные данные**: Проверьте пароль
   - Решение: Сбросьте пароль в панели Hetzner
